# Supplemental injury texture restoration

Supplemental maps belong to existing fighters and states. Inventory every alias,
index/name, source ID, dimensions, own alpha and corpus hashes independently.
A name such as br01 does not prove injury content, runtime binding or UV layout.

Establish an unwarped correspondence to that fighter's own clean source before
borrowing its accepted HD detail. The supported `damage_detail.restore` operation
requires equal square native RGBA crops and matching integer-scale HD references.
The default gate requires at least 75% exact native RGB agreement and nonempty
source differences; visual inspection is also required. Do not copy a published
fighter's head-quarter coordinates as proof for another asset.

## Offline assembly

1. Pin the clean restoration and original state hashes. The clean head is a
   cross-source reference, not a candidate parent of the supplemental source.
2. Start with exact accepted clean HD detail. Add the own faithful state RGB
   minus clean faithful RGB inside a two-native-texel transition around literal
   source changes. Record RGB clipping.
3. Use only bounded generated fine luminance inside exact source-change support,
   feathered inward. Calibrated values are ±3 Lab L at strength 0.8; the library
   bounds permissible parameters. Do not copy generated chroma, new wounds,
   shifted contours, swelling or invented writing.
4. Restore each state's own faithful alpha and inspected held RGBA tiles exactly.
   Keep clean RGB exact outside transition/holds. Never borrow sibling alpha or
   protect a whole restored garment just because it shares an auxiliary tile.

Preserve likeness, expression, painted lighting and original mark positions and
severity. Keep exact prompts, reference roles/hashes, outputs or failures,
processor version/parameters and clipping diagnostics privately. Clean references
already supply restored skin/hair material; this operation does not establish
authenticated high-resolution wound geometry or runtime shader parity.

An explicit `registration_rgb_tolerance` integer 1–3 supports separately audited
small palette quantization differences, requiring at least 50% exact and 80%
close RGB agreement. It does not relax geometry registration, erase small marks
from the literal change mask or authorize use on unrelated full-state atlases.
Default tolerance is zero. Inspected maps without injuries need their actual
material scope, not fabricated damage inferred from a filename.

## Review and native acceptance

Compare each state with its own original/faithful map and pinned clean reference.
Inspect mark boundaries, eyelids, mouth, hair, holds and named features after all
assembly. Import new revisions under their actual supplemental source IDs. Keep
notes/history and existing approval states; art review is separate from selection
or native verification. Use the gallery's all-maps/full-library filters for these
sources; an ordinary main-atlas model preview does not display injury switching.

A head substitution on existing geometry is only a labelled RGB diagnostic; do
not import it as a whole main-atlas pack replacement. Source inspection alone
does not establish the game's blend, mutable texture-copy path, damage thresholds
or material semantics. Verify identity, state switching, UV treatment, alpha,
mips and seams in actual fights/Story before claiming native acceptance.
Frozen batch/release evidence is indexed in [tooling history](tooling-history.md).
