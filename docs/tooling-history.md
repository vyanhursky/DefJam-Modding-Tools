# Maintained tools and historical recipes

The maintained package is `src/defjam_tools`, its synthetic tests and the current
workflow guides. It includes the gallery/model viewer, source decoder, scoped
assembly libraries and menu export/registration/compression tools. No dated
fighter batch script or production selection ledger is required at startup.

The complete fighter development snapshot is preserved on
[`codex/hd-fighters-beta` at d1c3de4](https://github.com/vyanhursky/DefJam-Modding-Tools/tree/d1c3de4).
Its `research/` tree retains source-specific assembly studies and frozen 0.1,
0.2 and 1.0 recipes with their original paths. It is historical evidence, not a
supported CLI or an active approval ledger. Never replay its reconnect/import/
review scripts into a current workspace. Local-neural trials remain experimental
and were excluded from the accepted 1.0 selection. Images, exact submissions,
reference photos, notes, checkpoints and release ZIPs stay in the private project.

HD Fighters 1.0.0 was published through catalogue PR10, with 218 source IDs
(200 restored, 12 Lanczos, 6 native inputs). Its immutable ZIP SHA-256 is
`1bea1239abb8e6b86fff85ecb9fbd0d805df2b1567183e6e8a16b6f131725e0f`.
The [frozen recipe](https://github.com/vyanhursky/DefJam-Modding-Tools/tree/6b00297e76fb1414c5cdf8ee90be99cfb4825fa1/research/hd-fighters-1-0-20261031)
and [catalogue change](https://github.com/vyanhursky/DefJamFFNY-mods/pull/10)
carry release evidence. This source cleanup does not rebuild, change or republish
that pack. Native Bonecrusher, injury/Story, alpha and mip playtests remain separate.

Production project records live in the existing private workspace, with its
backups and private handoff. The public application never bundles those ledgers
or uses old release IDs as current approval authority. Historical menu excerpts
already in `research/` are examples; [menu exporters](menu-exporters.md) require
explicit private inputs instead of bundled production tables.

## Follow-up boundaries

A small versioned job runner and portable offline release builder should replace
repeated dated orchestration in a separate change. They must pin inputs and
output bytes, distinguish candidate/Lanczos/native origins, validate explicit
selection/approval evidence and detect collisions/concurrent changes. Existing
style/labels are not authoritative generation-method metadata. Any metadata
schema change needs a versioned migration, backup and rollback; this integration
performs none.

R2 upload/public verification, catalogue entry generation, append-only signing
and released-client smoke checks belong in DefJamFFNY-mods. Runtime installation
and native game acceptance belong in DefJamFFNY-recomp. The gallery's local
Export action should not acquire publication or installation side effects.
